# Vibe Download Manager: browser extension

A browser extension that hands downloads to Vibe Download Manager ("Vibe"). It works in Chrome, Edge and
Brave (Manifest V3 service worker) and in Firefox 115 or later (MV3 event page).
It has no build step and no npm dependencies.

What it does:

- Captures browser file downloads, cancels them in the browser and sends the URL,
  referrer, cookies, user agent and file name to Vibe. If Vibe is missing or refuses
  the download, the browser downloads the file itself.
- Adds a "Download with Vibe" context menu entry for links, images, video and audio.
- Popup: shows whether Vibe is reachable, the videos found on the page, the
  "Capture browser downloads" switch, the minimum size to capture (KB) and the
  last error.

## Videos

The extension notices the HLS (`.m3u8`) and DASH (`.mpd`) playlists that a page
loads, and lets you send them to Vibe.

- Detection watches network responses (`webRequest`, observe only). A response
  counts as HLS when the URL path ends in `.m3u8` or the Content-Type is an HLS
  type (`application/vnd.apple.mpegurl`, `application/x-mpegurl`, ...). DASH
  works the same way with `.mpd` and `application/dash+xml`. Error responses
  (4xx, 5xx) are ignored.
- Each tab keeps up to 20 streams in `storage.session`, newest first. A URL is
  listed once. The first HLS playlist (usually the master) and the first DASH
  manifest are marked primary and shown first in the popup.
- The toolbar badge shows how many streams the tab has. The list clears when
  the tab navigates to a new URL, and when the tab closes.
- In the popup, "Download with Vibe" sends the stream URL to Vibe with the page
  as referrer, plus the cookies for that URL. Vibe downloads the playlist itself.

The extension does not fetch or convert the stream. It only hands the URL over.
A player that never requests a playlist (for example one that loads media
segments directly) leaves nothing to detect.

## Prerequisite: register the native host

The extension talks to `vdm-nmhost` through native messaging (host name
`com.vdm.native`). Register the host first:

```
vdm-nmhost install
```

The popup shows "Connected to Vibe <version>" once the host answers.

## Load it unpacked

**Chrome / Edge / Brave**

1. Open `chrome://extensions` (or `edge://extensions`).
2. Turn on **Developer mode**.
3. Click **Load unpacked** and select the `extension` folder.

The manifest includes a fixed `key`, so the extension id is always
`gepekebdmobfjhpghgflnhgbbmjcmhon`. That is the id the native host allows.

**Firefox**

1. Open `about:debugging#/runtime/this-firefox`.
2. Click **Load Temporary Add-on** and select `extension/manifest.json`.

A temporary add-on is removed when Firefox restarts. Load it again after a restart.

## Other download managers

If another download manager's browser integration is active, it can grab
downloads at the network level before the browser, and so before this extension,
ever sees them. Turn
that integration off for downloads to reach Vibe.

## Tests

From the repository root:

```
node --test extension/test
```

Regenerate the icons (the output is deterministic):

```
cargo xtask icons
```

## Layout

| File | Purpose |
|---|---|
| `manifest.json` | MV3 manifest (Chrome uses `service_worker`, Firefox uses `scripts`) |
| `decide.js` | Pure capture rules and message building, shared with the tests |
| `background.js` | Download and context-menu listeners, talks to the native host |
| `popup.html`, `popup.js`, `popup.css` | Toolbar popup |
| `icons/` | Generated by `cargo xtask icons` (same drawing as the app icon) |
| `test/` | `node:test` unit tests |
